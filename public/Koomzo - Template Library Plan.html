Plan · validated and built

Template Library — sample menus and floor plans

Koomzo staff build ready-made menus and floor plans for each kind of venue — maquis, bar, snack, hotel restaurant… A new customer picks one during setup, gets their own copy, and edits it. Fewer empty screens on day one, and faster onboarding.

Validated 15 Oct 2026 — all proposed answers accepted (D1–D8), full starter library. Built and checked against the acceptance list — see Cross-check. Try it: Template Library (also in Control Centre → Templates) and Restaurant → Setup → Menu / Floor plan → Templates.

Goal

Platform owner (Koomzo staff)

Creates, edits, previews and publishes templates in the Control Centre. Uses the same Menu and Floor plan editors customers use, plus CSV import. No code changes needed to add a template.

New customer (tenant)

During onboarding, or any time from Setup, picks a template that fits the venue. Sees a preview, picks Replace or Add to mine, and gets a copy they fully own.

Decisions to validate

Proposed answers in bold. Change any of them in your reply.

#QuestionProposedWhy
D1Copy or link?Copy. The customer gets their own copy; later template changes never reach existing customers.Customers change prices and dishes on day one. A link would overwrite their edits or block template updates.
D2One library for menus and floor plans, or two?One Templates screen, two kinds (Menu, Floor plan) shown as tabs. Optional bundle pairing: a menu template can suggest a floor template ("Maquis menu" + "Maquis layout").One place to manage. Bundles help onboarding: one choice sets up both.
D3Template lifecycleDraft → Published → Archived, with a version number. Only Published templates are shown to customers. Publishing again creates the next version.Staff can work on a template without customers seeing it half-done. Archived templates stay readable for audit.
D4Prices in a menu templateCopy the sample prices, marked "Check price" on each dish until the customer edits or confirms it. The marking disappears in one tap with Confirm all prices.A price is the thing most likely to be wrong for a given city. A marking catches it without blocking sales.
D5Who sees which templateFiltered by venue type and country/currency; the customer can switch to "Show all".A Douala maquis should not see a Paris brasserie first. Currency must match the tenant's currency.
D6Applying to an account that already has dataTwo modes: Replace (floor: only when no table is open; menu: open orders keep their lines) and Add to mine (menu: merged by dish name; floor: areas added alongside).Matches the CSV import already built, so the behaviour is the same everywhere.
D7LanguageOne template per language (FR / EN tag). No automatic translation.Dish names are local ("Ndolé", "Poulet DG"); translating them is wrong more often than right.
D8Track usageYes: each copy records template id + version + date. The Control Centre shows "Used by N customers".Shows which templates work; supports later "a new version is available" notices without auto-updating (D1).

Data model

Shared by both kinds. content uses exactly the shape the Restaurant module already stores, so applying a template is a plain copy.

Template
{ id, kind: 'menu' | 'floor', name, description, venueTypes: ['maquis','bar',…], locale: 'fr' | 'en', currency: 'XAF', status: 'draft' | 'published' | 'archived', version, publishedAt, updatedBy, updatedAt, pairWith: templateId | null, // D2 bundle content }
content by kind
menu: { categories: [{id,label,icon}], items: [{cat,name,desc,price, station,tags,icon,tint}] } floor: { areas: [{label,icon, tables:[{label,seats,shape,x,y}]}], rules?: { voidRule, printKitchen } }
Copy record (on the tenant)
{ templateId, version, kind, appliedAt, mode: 'replace' | 'add', appliedBy } dish.priceCheck = true // D4, until edited

Prototype storage: templates live in a shared kz:tpl store that both the Control Centre and the Restaurant module read. In production this becomes a platform-level collection (read-only to tenants, write for the Template editor role).

1 · Library
Control Centre → TemplatesMenu / Floor plan tabs. Cards: name, venue types, language, status, version, dish or table count, "Used by N". Filters: kind, venue type, status, language. Search.
2 · Create
New templateFrom blank, Duplicate an existing one, or Import CSV (menu; same format as the Restaurant import).
3 · Edit
Same editors as customersThe Menu editor and Floor plan editor already in Restaurant Setup, bound to the template rather than to a venue. Plus a details panel: name, description, venue types, language, paired template.
4 · Preview
See what the customer seesShows the register tiles (menu) or the floor plan exactly as they'll look after copying.
5 · Publish
Publish v2Checks: at least one category and dish / one area and table; every dish has a price and a station. Draft edits never touch the live version until published.
6 · Retire
ArchiveHidden from customers, kept for audit. Existing customer copies are untouched (D1).

Acceptance checklist

After building, I check every line against the result and mark it Pass or Fail, with notes.

  • A1Control Centre has a Templates screen with Menu and Floor plan tabs, filters and search.
  • A2Staff can create from blank, duplicate, and import a menu from CSV.
  • A3Template editing reuses the Restaurant Menu and Floor editors; Restaurant Setup behaves as before.
  • A4Draft → Published → Archived works; publishing bumps the version; publish is blocked with a clear reason when checks fail.
  • A5Only published templates appear to customers, filtered by venue type and currency, with "Show all".
  • A6Empty Menu / Floor plan screens offer "Start from a template" first.
  • A7Preview states the impact before applying; Replace and Add to mine follow D6; floor Replace is refused while a table is open.
  • A8Applied content is a copy: editing the template later does not change the customer; editing the customer copy does not change the template.
  • A9Copied dishes carry "Check price" until edited or confirmed; the banner count is correct.
  • A10Copy record is saved; "Used by N" updates in the Control Centre.
  • A11Bundle: picking a paired menu offers the matching floor plan, and the reverse.
  • A12Undo restores the state from just before applying.
  • A13Phone layout: single-column gallery, full-screen preview, sticky action, targets ≥ 44 px.
  • A14Starter library present: 4 menus + 6 floor plans.
  • A15No console errors on the Control Centre or Restaurant & Bar pages.

Out of scope (v1)

Pushing template updates to existing customers. D8 records enough to add a "new version available" notice later.
Customer-made templates (a chain sharing one menu across branches) — a natural v2 on the same model.
Product photos in templates — tiles use icon + colour until there's media storage.
Retail Flex catalogues — the same model fits, but only after Restaurant is validated.
